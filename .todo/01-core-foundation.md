# 01 - Core foundation: app shell, i18n, storage, layouts, words, input

Specs: `.specify/architecture.md`, `.specify/learning/*`, `.specify/profiles/profiles.md`,
`.specify/experience/localization.md`. Read them first.

## Why
Every later plan (game, levels, Piko, polish) builds on these modules. They are pure
logic and can be unit-tested well, so they come first.

## Decisions (binding for all plans)
- Stack: Vite + TypeScript (strict), no UI framework. DOM screens are small classes or
  functions that render into `#app`; game scenes draw on one `<canvas>`.
- Source layout under `src/`:
  - `app/` - boot, screen router (`start`, `profiles`, `map`, `level`, `parent`,
    `wardrobe`, `stats`, `about`), app state.
  - `i18n/` - loader + `t(key, params)`; files `public/i18n/sk.json`, `public/i18n/en.json`
    fetched with `import.meta.env.BASE_URL` prefix.
  - `storage/` - versioned store (`pikotyper:v1` key), profile CRUD, guest profile
    (kept in memory / `sessionStorage`), export/import JSON, migrations map.
  - `keyboard/` - layout definitions (`sk-qwertz`, `us-qwerty`) as data: rows of physical
    keys (`KeyboardEvent.code`), the char for normal/shift, finger index (0-9), dead-key
    compositions; layout mismatch detector.
  - `input/` - one `keydown` listener producing typed characters. Dead keys: when
    `event.key === 'Dead'`, remember `event.code` and the shift state; the next keydown
    whose `key` is a composed char (browser already composes it) is used as is. Map
    dead-key steps to the guide using the layout's composition table. Ignore auto-repeat
    (`event.repeat`) and modifier-only keys. `preventDefault` for handled keys while in a level.
  - `words/` - dictionary loader (`public/words/sk.json`, `public/words/en.json`), filter
    by active keys, length range, diacritics toggle; weighted picker by weak keys;
    pseudo-word generator (consonant/vowel alternation from allowed keys, small block
    list, pattern drills like `fff jjj fj` for 2-4 keys); seedable RNG for tests.
  - `learning/` - lesson key order per layout, mastery rule, active key set resolver
    (automatic vs parent-picked), per-key stats recorder (presses, errors, reaction ms,
    wrong-instead counts), session trend records.
- Mastery rule: last 40 presses of a key with accuracy >= 92 % and median reaction
  <= 1200 ms at difficulty 5 (scale 1600 ms at 1 to 800 ms at 10). Then unlock the next key.
- Lesson order sk-qwertz: `f j d k s l a ô g h e i r u o t n c v m p ...` then the upper
  and lower rows, then diacritics `á í é ý ž ť č š ľ ú ä ň ó ĺ ŕ ď`, then Shift capitals,
  then digits. us-qwerty: same idea with `;` instead of `ô`, no diacritics.
- Word lists: about 1000 child-friendly words per language, generated by the implementing
  session from its own knowledge, lowercase, NFC normalized, no proper nouns, nothing
  scary or rude. Structure: `{ "words": ["..."] }` (filtering happens at runtime).
- All strings in i18n files; Slovak texts must be natural Slovak with correct diacritics.
- Storage schema v1 (TypeScript types are the contract): `Profile { id, name, avatar,
  companion { name, kind, accessories[] }, customMessages[], layout, language,
  settings { activeKeysMode, manualKeys[], wordLen [min,max], difficulty, noDiacritics,
  noTimePressure, sessionMinutes, guide, sfxVolume, musicVolume, font, reduceMotion,
  highContrast }, progress { unlockedKeys[], levels {id: stars}, worldsDone[], rewards[] },
  stats { keys {char: KeyStat}, sessions[] } }`.
- Unit tests with Vitest next to modules (`*.test.ts`).

## Steps
- [ ] i18n loader + sk/en base files + browser detection (fallback en) + tests
- [ ] storage: schema types, load/save, migrations hook, guest mode, export/import
      (validate shape, "replace or keep both") + tests
- [ ] keyboard layouts sk-qwertz and us-qwerty as data + finger map + dead-key table +
      mismatch detector + tests (y/z swap, digits vs ľščť)
- [ ] input module with dead-key handling + tests using synthetic KeyboardEvents
- [ ] word lists sk/en (~1000 each) + filter + weighted picker + pseudo-word generator
      + block list + tests (tiny key sets, diacritics toggle, length range)
- [ ] learning: lesson order, mastery rule, active key resolver, stats recorder + tests
- [ ] app shell: router, start screen with language switch, profile list/create/guest,
      minimal free-practice screen (DOM text, no canvas yet) proving the full pipeline:
      words -> input -> stats -> storage
- [ ] `npm run build` and `npm test` green; push (CI deploys)

## Affected
New `src/*` modules, `public/i18n/*`, `public/words/*`. No backend, no DB.
localStorage key `pikotyper:v1` is the data contract for all later plans.
